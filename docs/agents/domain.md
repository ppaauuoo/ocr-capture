# Domain Docs

## Before exploring

- Read `GLOSSARY.md` at the repo root if it exists.
- Read relevant ADRs under `docs/adr/` if they exist.
- Proceed silently when these files are absent; create them only when domain terms or decisions are resolved.

## Use the glossary

Use the glossary's terms in issue titles, refactor proposals, and tests. If a needed concept is missing, reconsider whether the term belongs in this project or note the gap for domain modeling.

## Flag ADR conflicts

Surface any proposal that conflicts with an existing ADR rather than silently overriding it.
